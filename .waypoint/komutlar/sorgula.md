# `sorgula` — question an idea until it's clear

Runs at stage 1 and before a big new feature (something new I'll see or use, or more than one task); skip it for small fixes. I can also type `sorgula`.

1. While questioning, keep a brief temporary `## Aktif sorgulama` section in `ILERLEME.md`, right under "Proje hedefi" (create it when needed). Note the topic, clear requirements, unapproved assumptions, open questions and the next question. After each meaningful answer, update it **before asking the next question**. Write short bullets, not a transcript. This draft is not a confirmed goal, plan or entry in `Kararlar`; don't create another file.
2. Ask only product questions (what it does, who uses it, what I see when, edge cases), basics first, one per message, each with your recommendation worded so "evet" accepts it. Never answer a decision for me. At stage 1, also ask the product questions that decide the technology, unless already clear: where it runs (phone, computer, browser, a server), whether others will install or use it, how fast it must be and how much it handles (big files, many users, instant response), whether it must work offline, whether paid services are OK, and which existing program or file it must work with. Never ask me to pick a language or framework: `arastirma.md` chooses it from these answers.
3. Ask again only if an answer conflicts with an earlier one or leaves an important case unclear, not just because it came quickly. "Bilmiyorum" is valid: treat your recommendation as a temporary assumption (not a decision, never in "Kararlar"), park the question in "Sonra yapılacaklar" with "(cevap bekleniyor)" (only there, not also in the draft), and don't ask again now.
4. Stop when the important product unknowns are resolved and the goal or feature's "bitti sayılır" can be stated clearly. **There is no question-count limit.** About every 8 questions, tell me in 2 lines what's clear and what's still open, then go on; you decide whether to also ask me to stop or split the idea (do it when the idea keeps growing). If I say stop, stop.
5. Summarize in 3–5 plain lines and wait for my OK before building. If I pause, leave the draft so a later session can continue; do not treat it as approved. After my OK, record it: at stage 1 only "Proje hedefi" (the plan is still made and approved in stage 2); for a feature, its task's "bitti sayılır" line. Only real choices I made go into "Kararlar". Then remove the temporary "Aktif sorgulama" section from `ILERLEME.md`.
